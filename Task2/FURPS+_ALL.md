# FRUPS+ — Все требования

| Код  | Требования                                                                 | Комментарий                                                                                                      |
|------|-----------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------|
| F    | **Функциональные (Functionality)**                                              |                                                                                                                  |
| F1   | Просмотр списка доступных депозитов и актуальных ставок на сайте            |                                                                                                                  |
| F2   | Подача заявки на депозит с сайта (передаем номера телефона, ФИО)            |                                                                                                                  |
| F3   | Просмотр заявки на депозит в системе кол центра                              |                                                                                                                  |
| F4   | Фиксация результатов звонка с клиентом в системе кол центра                 | Явно не отражено в описании требований, но необходимо для дальнейшего подтверждения в АБС                       |
| F5   | Просмотр актуальных базовых ставок по депозитам  в системе кол центра       | Явно не отражено в описании требований, но необходимо для консультации клиента по заявке                        |
| F6   | Просмотр списка депозитов с актуальными и персонализированными ставками в интернет банкинге  |                                                                                  |
| F7   | Подача заявки на открытие депозита в интернет банкинге (передаем счет списания + сумма депозита) |                                                     |
| F8   | Подтверждение операции в интернет-банке через СМС-код                       |                                                                                                                  |
| F9   | Подтверждение условий и ставки депозита в АБС бэк-офисом                     |                                                                                                                  |
| F10  | Получение СМС-уведомления клиентом после подтверждения ставки/условий и после открытия депозита |                                            |
| F11  | Управление ставками депозитных продуктов для сотрудника бэк офиса кредитования |                                                                                                                |
| F12  | Отображение ставок по депозитам для сотрудника бэк офиса депозитов          |   
| F13   | Просмотр списка доступных кредитных продуктов и актуальных условий на сайте | |
| F14   | Подача заявки на кредит с сайта с указанием номера телефона и Ф. И. О. | |
| F15   | Подача заявки на кредит с сайта с указанием паспортных данных для получения мгновенного решения | |
| F16   | Получение решения по заявке нового клиента на основе данных системы кредитного скоринга и БКИ | |
| F17   | Отправка клиенту СМС-уведомления о необходимости посещения отделения для идентификации и получения кредита | |
| F18   | Продолжение обработки ранее созданной заявки по предодобренному кредиту (сайт → отделение) | |
| F19   | Просмотр списка доступных кредитов и актуальных условий в интернет-банкинге | |
| F20   | Отображение предодобренного кредитного предложения в интернет-банкинге | |
| F21   | Повторный скоринг заявки по упрощённой процедуре при подаче заявки по предодобренному предложению | |
| F22  | Подача заявки на кредит в интернет-банкинге с указанием счёта зачисления средств | |
| F23  | Подтверждение подачи заявки на кредит в интернет-банкинге через СМС-код | |
| F24  | Информирование клиента по СМС об изменении статуса заявки на кредит | |
| F25  | Статусы заявки должны быть едиными и согласованными | Доп. требование: явно не отражено в описании, но без него невозможно корректно реализовать F24 |                                                                                                               |
| U    | **Удобство использования (Usability)**                                          |                                                                                                                  |
| U1   | Сайт и интернет-банк должны соответствовать принятой дизайн-системе         |                                                                                                                  |
| U2   | Корректная работа сайта на мобильных устройствах (адаптивность)             | Доп. требование: сайт — публичный канал, ошибки UI/доступности влияют на продажи и репутацию.                  |
| R    | **Надёжность (Reliability)**                                                    |                                                                                                                  |
| R1   | Доступность сервисов 24/7 и 99,9%                                           |                                                                                                                  |
| R2   | Избегать прямых синхронных вызовов интернет-банка к API АБС в новом процессе |                                                                                                                  |
| R3   | При сбое ЦОД сервис должен быть доступен; поддержка переключения на резервный ЦОД |                                                                                                             |
| R4   | Заявки и события не должны теряться; повторная отправка должна быть безопасной (идемпотентность) | Доп. требование: иначе будут “пропавшие” заявки и двойные СМС/операции |
| R5   | Метрики доступности, задержек, ошибок                                       | Доп. требование для достижения 99,9% и управляемости.                                                           |
| R6   | Защита персональных данных                                                  | Доп. требование (обоснование): сайт и IB обрабатывают ПДн; без этого высокие юридические и репутационные риски. |
| R7   | Предусмотреть ролевую модель                                                | Доп. требование (обоснование): ставки и “особые условия депозитов” — зона повышенного риска злоупотреблений.   |
| P    | **Производительность (Performance)**                                           |                                                                                                                  |
| P1   | Очень быстрый отклик (миллисекунды) в клиентских каналах                    |                                                                                                                  |
| P2   | Устранить проблему “справочные данные > 1 секунды” при операциях            |                                                                                                                  |
| P3   | Горизонтальное масштабирование сервисов                                     |                                                                                                                  |
| P4   | Балансировка запросов между серверами/приложениями/ЦОД                     |                                                                                                                  |
| P5   | Пиковая нагрузка на сайт и IB не должна деградировать АБС                  |        
| P6   | Предодобренные заявки должны быть обработаны сотрудниками в течение того же рабочего дня |  |                                                                                                          |
| S    | **Поддерживаемость (Supportability)**                                          |                                                                                                                  |
| S1   | Документация для дальнейшего расширения: API-контракты, схемы интеграций, описания процессов и статусов заявки |                                  |
| S2   | Трассировка и диагностика: корреляционные ID, централизованные логи        | Доп. требование: критично при распределённой архитектуре и SLA 99,9%                                           |
| S3   | возможность подключить новые продукты/каналы без переписывания ядра        | Доп. требование: снижает стоимость последующей цифровизации других продуктов.                                  |
| +R   | **+ Ограничения (Restrictions)**                                               |                                                                                                                  |
| +R1  | Шифрование трафика для сайта и интернет-банка при передаче данных (TLS)|                                  |
| +R2  | Минимизировать доработки подрядчика в функционале СМС, использовать внутреннюю разработку |                                  |
| +R3  | Очереди сообщений — предпочтительно Kafka “на перспективу”, но текущая платформа интернет-банка несовместима |                             |
| +R4  | Возможная миграция интернет-банка к микросервисной архитектуре — только в рамках задачи депозитов |                              |
| +R5  | АБС: вертикальное масштабирование из-за БД; нельзя планировать решение, которое требует горизонтального масштабирования АБС |        |
| +R6  | MS SQL и/или Oracle для хранения данных; совместимость с текущими платформами разработки |                                   |
| +R7  | Взаимодействие с БКИ, SMS-шлюзом и кредитным конвейером должно быть асинхронным | Доп требования: недоступность внешних систем не должна блокировать пользовательские сценарии |
| +R8  | Запрещено проектировать решение, в котором потребители получают списки продуктов/ставки через прямые синхронные запросы к АБС на каждое пользовательское действие. Допускается только получение этих данных из выделенного read-слоя (витрина/кэш), синхронизируемого с АБС по расписанию или событиям | Доп требования: использование АБС как справочника создаёт риск деградации ядра при пиковом трафике |
| +R9  | Система кредитного скоринга не должна нагружаться фоновыми или периодическими предрасчётами |   
| +R10  | Клиентские каналы не должны инициировать скоринг чаще одного раза на заявку/событие | |   
| +R11  | Заявка на кредит должна иметь единый сквозной идентификатор во всех каналах и системах |Доп требование: Основа сценария «продолжения заявки» |
| +R12  | Нельзя ускорять обмен заявками между АБС и Кредитным конвейером чаще существующего регламента |  |
